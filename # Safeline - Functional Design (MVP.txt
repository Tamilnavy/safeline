# Safeline - Functional Design (MVP)

## 🧩 Roles

### Base Roles
- **Employee** → all users
- **Admin** → organization setup (no complaint access by default)
- **Owner** → highest authority (optional oversight)

### Committee Permissions (assigned on top of Employee)
- **Complaint Handler**
- **Committee Lead**
- **Escalation Head**

> Note: One user can have multiple roles.

---

## 🔐 Core Principles

1. Login is required (prevents spam)
2. Anonymous complaints hide identity from committee
3. Identity is stored separately (secure mapping)
4. Complaints are immutable (no edit/delete after submission)
5. Access is controlled by role + assignment
6. Conflict-of-interest rules must be enforced

---

## 📥 Complaint Types

### 1. Normal Complaint
- Against employees or general issues

### 2. Sensitive Complaint
- Against:
  - Committee members
  - HR
  - Leadership
- Triggered by:
  - User checkbox OR
  - System auto-detection (recommended)

---

## 🔄 Complaint Flow

### Step 1: Employee Submission
- Login required
- Select:
  - Category
  - Accused person (optional)
- Choose:
  - Anonymous / Named
- Optional:
  - Mark as "against committee member"

---

### Step 2: System Routing

#### Normal Complaint
- Visible to → **Committee Lead**

#### Sensitive Complaint
- Visible to → **Escalation Head only**
- Hidden from:
  - Committee Members
  - Committee Lead

---

### Step 3: Assignment

#### Normal Complaint
- Committee Lead:
  - Reviews complaint
  - Assigns to Complaint Handler

#### Sensitive Complaint
- Escalation Head:
  - Handles directly OR
  - Assigns special handler

---

### Step 4: Investigation

Handled by:
- Complaint Handler (normal)
- Escalation Head (sensitive)

Actions:
- Add notes
- Request info (anonymous chat)
- Review evidence
- Update status

---

### Step 5: Communication

- Two-way chat enabled
- Works in anonymous mode
- Identity is never revealed

---

### Step 6: Status Workflow

- Submitted
- Under Review
- Investigating
- Resolved
- Closed

---

### Step 7: Closure

#### Normal
- Handler updates
- Committee Lead closes

#### Sensitive
- Escalation Head closes

---

## 👀 Visibility Rules

### Employee
- Can view only their own complaints

---

### Complaint Handler
- Can view only assigned complaints
- Cannot:
  - See anonymous identity
  - Access unassigned/sensitive complaints

---

### Committee Lead
- Can view all normal complaints
- Can assign handlers
- Cannot:
  - See anonymous identity
  - Access sensitive complaints

---

### Escalation Head
- Can view:
  - Sensitive complaints
  - Escalated cases
- Can handle and close

---

### Admin
- Can:
  - Manage users, categories, organization setup
- Cannot:
  - View complaints (by default)

---

## 🚫 Conflict Rules

- Accused person must NEVER access the complaint
- If accused is a committee member:
  - Route to Escalation Head only
- System should auto-detect conflicts (not only rely on checkbox)

---

## 🔒 Anonymity Logic

- User logs in → system generates `anonymous_id`
- Complaint stores only:
  - anonymous_id (not user_id)
- Identity mapping stored securely
- Committee never sees real identity

---

## 📊 Data Model (Simplified)

### Users
- id
- roles

### Complaints
- id
- anonymous_id
- category
- description
- accused_user_id (optional)
- type (normal / sensitive)
- status
- assigned_to

### Identity Mapping (Secure)
- user_id ↔ anonymous_id

### Audit Logs
- action
- user
- timestamp

---

## ⚡ Flow Summary

Employee submits complaint → system classifies (normal/sensitive) → routed to Committee Lead or Escalation Head → assigned → investigated → resolved → closed

---

## 🚀 MVP Scope

1. Login + role system
2. Complaint submission (anonymous option)
3. Routing (normal vs sensitive)
4. Assignment system
5. Status tracking
6. Anonymous chat
7. Basic dashboard
